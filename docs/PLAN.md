# План работ

Этапы идут по порядку. Следующий этап начинается, когда у предыдущего выполнены критерии приёмки и владелец посмотрел результат. Каждый этап - отдельная ветка и PR.

## Модель и effort по этапам

Правило: сложное и необратимое - сильная модель. Механическое - модель попроще.

| этап | модель | effort | почему |
|---|---|---|---|

| 2a. Маскот: пружины, тело, глаза, поведение | Opus 5.5 | high | точный перенос формул и таймингов, ошибки тонкие |

| 2c. Карточки, вкладки, плеер, приветствие | Sonnet 5.5 | high | объёмно, но по готовому образцу из прототипа |

- Haiku для этого проекта не подходит, кроме совсем мелочей вроде правки текста в docs.
- Переключение: `/model` и `/effort` в Claude Code или переключатель в окне.

## Этап 0. Каркас репозитория
- Монорепо на npm workspaces: `packages/island`, `apps/harness`, `apps/desktop`. TypeScript strict, ESLint, Prettier, Vitest.
- Корневые скрипты: `dev:harness`, `parity`, `ref:screens`, `ref:clips`, `test`, `desktop:dev`.
- **Приёмка:** `npm install && npm test` проходит; `npm run ref:screens` воспроизводит текущий `reference/screens` без отличий.

## Этап 1. Проверка окна (до любого переноса)
Самый большой риск проекта, поэтому он первый.
- Tauri-окно с чёрной полосой-заглушкой на Mac у выреза:
  - поверх строки меню, на всех рабочих столах;
  - клики насквозь вне полосы;
  - при наведении полоса раскрывается в прямоугольник 480×150 и сворачивается при уходе курсора.
- То же на Windows у верхнего края. Проверить на виртуалке, если основной машины с Windows нет под рукой.
- Ширина выреза берётся из системы, а не из константы.
- **Приёмка:**
  - короткое видео или GIF с Mac: полоса на месте выреза, клик сквозь пустую область окна попадает в приложение под ним, наведение раскрывает;
  - список того, что не получилось.

  Если не получилось главное, переходим на запасной путь из ARCHITECTURE и согласуем с владельцем.

## Этап 2. Перенос маскота и острова в packages/island + харнесс
Делится на четыре сессии - 2a, 2b, 2c, 2d (см. таблицу выше). После каждой - коммит, обновлённый PROGRESS.md и промпт на следующую часть.
- Перенести рендер и поведение по SPEC, данные - из заглушек `stub.ts`.
- Харнесс повторяет страницу прототипа, есть `window.__notch`.
- Детерминизм: `rng`, виртуальное время.
- **Приёмка:**
  - `npm run parity` - все кадры в пределах 1%;
  - ролики сверены на глаз;
  - чек-лист `docs/PARITY.md` отмечен полностью.

## Этап 3. Остров в настоящем окне
- `apps/desktop` монтирует `packages/island` во всё окно. Клики насквозь по `islandRect()` и `hitTest`. Геометрия выреза из системы. Состояния «Авто».
- Отладочное меню (трей): вызвать любое событие, как кнопки 1-0 и Q в прототипе.
- **Приёмка:** на Mac выглядит как кадры `reference/screens` в реальном размере; лупа не нужна - смотрим на ретине глазами. Все события вызываются из трея.

## Этап 4. Claude Code
- Сервер хуков, установщик хуков с диффом и бэкапом, события attention, question, working (шаги), thinking, searching, success и error сессии.
- Ответы из острова уходят обратно в хук.
- Plan usage из локальных логов, лимит с таймером.
- **Приёмка:** реальная сессия Claude Code в терминале и в Claude Desktop показывает шаги в острове; разрешение команды из острова работает; при выключенном приложении Claude Code работает как обычно (хук не блокирует).

## Этап 5. Календарь и музыка
- Mac: EventKit, текущий плеер. Обложка - реальная.
- **Приёмка:** созвон из календаря появляется в карточке и в автовыборе; плеер управляет реальной музыкой (плей, пауза, треки, перемотка, громкость).

## Этап 6. GitHub
- Токен в Keychain, выбор репозиториев, CI, PR, коммиты за 7 дней.
- **Приёмка:** реальные данные, успех и ошибка CI вызывают события острова.

## Этап 9. Полировка (после этапа 8)

Решение владельца 2026-10-18: делаем после всего этапа 8, отдельной веткой `stage-9-polish`.

- Звуки: короткие отклики на события острова и модулей (разрешение, вопрос, агент закончил, итоги), как в coucou, но свои - собственные сэмплы, без чужих файлов. Громкость и выключатель в настройках (кнопка динамика в верхней панели), по умолчанию тихо.
- Анимации: раскрытие, переходы между модулями, вкладками и карточками плавные, не хуже coucou и AB.design. Пружины и тайминги прототипа не трогаем, добавляем только там, где в прототипе резкий скачок.
- Эффект наведения на модули: подсветка или лёгкое приподнимание иконки, чипа и карточки под курсором.
- Полноценный экран настроек: все модули, подключения, внешний вид, звуки, язык, горячие клавиши в одном окне с разделами.
- Меню настроек красивее и плавнее, не хуже coucou: анимация открытия, переходы между разделами, аккуратные переключатели и списки.

### Вкладка «+»: полка файлов вместо списка модулей

Сейчас вкладка «+» (`packages/island/src/island/tabs.ts`, `drawAdd`) - сетка «Почта, Notion, Obsidian, n8n, Vercel, Grafana». Это повтор настроек модулей, пользы ноль. Решение владельца 2026-10-18: заменить её временным хранилищем файлов для последующей отправки, как в coucou. Разбор того, как это сделано в coucou, и что брать нельзя - `docs/polish-refs/README.md`, раздел 7.

Что должно получиться:
- Файл можно бросить на остров откуда угодно (и на закрытый, и на открытую вкладку «+»); остров раскрывается навстречу.
- Вкладка «+» - зона сброса: пунктирная рамка, маскот, «Перетащите файлы сюда», подсказки типов. Пока файл несут над островом - рамка и свечение меняют цвет.
- Бросок - маскот реагирует (своя анимация «проглотил», свой звук), файл копируется в нашу временную папку, оригинал не трогаем.
- После броска - «Файл готов, что с ним сделать?»: спросить о файле в чате, отправить письмом, а также то, чего нет в coucou и что нужно для «последующей отправки»: оставить на полке, вытащить обратно перетаскиванием в любое приложение (Telegram, браузер, Finder), показать в Finder.
- Полка держит несколько файлов, видно имя, размер, тип; файл можно убрать.
- Временная папка чистится сама (срок решит владелец), при выходе из приложения ничего лишнего не остаётся без спроса. Приватность: файлы никуда не уходят, пока пользователь сам не отправил.
- Каждое решение - с записанной причиной: почему иконка, порядок кнопок, звук и анимация именно такие, а не проще.

Спросить у владельца до начала: сколько файлов держит полка, срок хранения, какие действия после броска и в каком порядке, нужен ли «отправить письмом» (в coucou - Apple Mail или Resend).

Референсы владельца - `docs/polish-refs/`, разбор по каждому кадру - `docs/polish-refs/README.md`. Это обязательная планка, а не пожелание: наполнение, раскладка, кнопки, свечение по типу события, состояния маскота - не хуже референса в каждом пункте разбора. Перед работой открыть все 6 кадров.

Критерии приёмки:
- Всё, что меняет вид или поведение острова относительно прототипа, сначала записано в `docs/CHANGES.md` и подтверждено владельцем.
- Видео до и после для анимаций и наведения, `npm run parity` без новых красных кадров.
- Звуки выключаются одним кликом и не играют, когда выключены.
- Полка файлов: бросок из Finder и браузера, вытаскивание обратно, очистка временной папки проверены руками и тестами; во вкладке «+» больше нет списка модулей.
- Скриншоты тех же экранов рядом с референсами, по каждому пункту `docs/polish-refs/README.md` - сделано или почему нет.
